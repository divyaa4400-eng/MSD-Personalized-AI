# Personalized AI-Enabled Musculoskeletal Disorder Risk Assessment — Reproducibility Repository

This repository provides an end-to-end computational implementation of the framework described in the manuscript **“Personalized Risk Assessment of Musculoskeletal Disorders Using Artificial Intelligence Enabled Predictive Imaging Models.”**

The implementation is intentionally self-contained: it generates a deterministic synthetic multimodal cohort, preprocesses MRI/CT/X-ray surrogates and structured clinical/biomechanical variables, trains modality-specific convolutional encoders, performs gated-attention multimodal fusion, predicts continuous and categorical musculoskeletal-disorder (MSD) risk, evaluates calibration and robustness, runs baseline and ablation experiments, and generates machine-readable results and publication-oriented figures.

> **Important data-provenance statement:** This repository does not contain patient records, protected health information, human tissue data, or hospital-derived clinical records. The default experiments use a fully synthetic cohort generated by `src/synthetic_data.py`. The code must not be represented as evidence of prospective or retrospective human-subject recruitment.

## Scientific objective

The computational task is personalized MSD risk estimation from five information streams:

1. MRI-like synthetic imaging,
2. CT-like synthetic imaging,
3. X-ray-like synthetic imaging,
4. clinical/demographic variables, and
5. biomechanical variables.

A gated-attention fusion module learns context-sensitive weights across modalities and feeds a dual-head prediction network:

- a regression head for continuous risk score in `[0, 1]`, and
- a classification head for low/moderate/high risk stratification.

The repository also reproduces the manuscript's principal validation categories: cross-validation, independent testing, calibration, baseline comparison, ablation, missing-modality robustness, noise sensitivity, statistical comparison, and explainability.

## Installation

Python 3.10 or later is recommended.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell
# .venv\Scripts\Activate.ps1

pip install --upgrade pip
pip install -r requirements.txt
```

`shap` is included for structured-feature attribution. If SHAP is unavailable on a constrained machine, the main training/evaluation pipeline still runs; explainability gracefully falls back to permutation-based grouped attribution.

## One-command reproduction

```bash
python run_full_pipeline.py --config configs/default.yaml
```

To execute the main, baseline, ablation, and robustness experiment families sequentially, run:

```bash
python run_all_experiments.py
```

The primary command performs:

1. deterministic synthetic cohort generation;
2. development/test split with a locked independent test set;
3. five-fold cross-validation inside the development set;
4. final model fitting on the full development set;
5. independent test evaluation;
6. calibration analysis;
7. grouped feature attribution and Grad-CAM generation;
8. statistical summaries;
9. figure generation; and
10. machine-readable result export.

Outputs are written by default to `outputs/`. The directory is generated at runtime and intentionally excluded from version control.

## Experimental design

The default synthetic cohort contains 1,200 subjects. The implementation uses an 85% development / 15% independent test design. Five-fold stratified cross-validation is performed only inside the development cohort. This interpretation prevents information leakage between model selection and final evaluation while remaining consistent with the manuscript's stated use of both an independent test set and five-fold cross-validation.

### Risk-label generation

A latent disease-burden variable is generated from demographic, clinical, and biomechanical factors. The imaging modalities are conditionally generated from this latent burden using different modality-specific image-formation functions and noise profiles. The final continuous risk target is a bounded non-linear combination of imaging, clinical, biomechanical, and interaction terms plus controlled annotation noise. Three risk categories are obtained using fixed thresholds defined in the YAML configuration.

### Imaging streams

The synthetic images are compact 2-D surrogates intended for computational reproducibility rather than diagnostic use. They emulate modality-specific contrast and structural effects:

- MRI-like: soft-tissue texture and degeneration-sensitive intensity patterns;
- CT-like: high-contrast bone structure and density-associated variation;
- X-ray-like: projection-style skeletal structure and joint-space changes.

The default resolution is 32×32 to keep complete experiments practical on CPU-only machines. Resolution is configurable.

## Proposed model

Each imaging modality is encoded with a small residual CNN. Clinical and biomechanical variables are separately embedded by multilayer perceptrons. All five embeddings are projected to a common latent dimension and fused by gated attention.

For modality embedding `h_m`, patient context `c`, and learnable parameters, attention is computed as

```text
e_m = v^T tanh(W_h h_m + W_c c + b)
a_m = softmax(e_m)
z   = Σ_m a_m h_m
```

A modality-availability mask is applied before softmax, enabling principled missing-modality experiments.

The fused representation is passed to regression and classification heads. Training uses a weighted joint objective combining weighted MSE and cross-entropy.

## Baselines

Run:

```bash
python run_baselines.py --config configs/baselines.yaml
```

The repository supports:

- logistic regression,
- random forest,
- support-vector machine,
- clinical-only multilayer perceptron,
- imaging-only CNN fusion,
- simple concatenation multimodal network, and
- proposed gated-attention multimodal network.

The repository also contains optional torchvision implementations of **ResNet101, DenseNet121, and ViT-B/16** imaging baselines. They are disabled by default because they substantially increase CPU/GPU runtime; set `advanced_baselines.enabled: true` in `configs/baselines.yaml` to execute them. No pretrained weights are downloaded and no reported manuscript metric is hard-coded.

## Ablation experiments

```bash
python run_ablation.py --config configs/ablation.yaml
```

Default ablations include:

- full model,
- no gated attention (mean fusion),
- no biomechanics,
- no clinical stream,
- imaging only,
- no uncertainty weighting,
- no residual connection, and
- no modality dropout.

## Robustness experiments

```bash
python run_robustness.py --config configs/robustness.yaml
```

Robustness tests include:

- missing MRI,
- missing CT,
- missing X-ray,
- missing clinical variables,
- missing biomechanical variables,
- paired missing modalities,
- Gaussian imaging noise,
- structured-variable noise, and
- increasing missingness rates.

The scripts report absolute performance and performance degradation (`ΔAUC`, `ΔF1`, and `ΔAccuracy`) relative to the uncorrupted test set.

## Evaluation metrics

The implementation reports, where applicable:

- accuracy,
- macro F1,
- ROC-AUC,
- one-vs-rest multiclass ROC-AUC,
- mean squared error,
- mean absolute error,
- Pearson correlation,
- Brier score,
- expected calibration error,
- confusion matrix,
- 95% bootstrap confidence intervals,
- fold mean ± standard deviation, and
- paired statistical comparisons across folds.

## Explainability

Two complementary explanation families are implemented:

- **Grad-CAM** for imaging encoders;
- **SHAP or permutation attribution** for structured clinical and biomechanical features.

Grouped attribution summaries quantify the relative influence of imaging, clinical, and biomechanical information. These outputs are computational model explanations and must not be interpreted as causal clinical effects.

## Reproducibility controls

The pipeline fixes seeds for Python, NumPy, and PyTorch and records:

- configuration snapshot,
- package versions,
- device information,
- split indices,
- fold-level metrics,
- final metrics,
- model parameter count, and
- runtime metadata.

Run the repository self-check with:

```bash
python verify_reproducibility.py
```

The verifier checks configuration validity, deterministic data generation, unique subject identifiers, absence of train/test overlap, target validity, model forward execution, finite metrics, and expected output generation.

## Result integrity

The repository does **not** embed the manuscript's claimed 92.3% accuracy, 0.94 AUC, or any other result as constants. Reported values are calculated from the configured experiment. A reproduction may yield different values depending on software version, device, configuration, and stochastic optimization. Such variation should be reported rather than suppressed.
